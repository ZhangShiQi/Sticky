# Sticky

一个本地优先的 Windows 便签工具。C# / .NET 10 / WPF。主程序不依赖第三方 NuGet 包；Windows x64 便携版内置 .NET 运行时、Git 和登录组件。

## 使用 Windows 便携版

从 [GitHub Releases](https://github.com/ZhangShiQi/Sticky/releases) 获取已发布的 Windows x64 便携包，或自行打包生成 `dist/Sticky-0.6.3-win-x64-portable.zip`，完整解压后双击根目录的 `Sticky.exe`。目标电脑不需要安装 .NET SDK、.NET Runtime 或 Git。请保留随包的 `tools` 文件夹，包含 WPF 程序、Git 和 Git Credential Manager。源码仓库不包含发布包；从源码获取后，可按下文运行打包脚本生成。当前源码版本为 0.6.3，已发布版本与更新记录见 Releases。

便携版自动将数据存到 exe 旁边的 `Data`，不依赖当前工作目录，也不读取开发预览 `.local-demo` 中的便签。发布包是空白工作空间，不包含开发机上的便签、仓库配置、Git 历史或凭据。原有便签可先导出 ZIP，再在便携版导入。

在另一台电脑测试同步时，填写相同仓库和分支，并在该电脑完成 GitHub 登录。登录凭据由各电脑的系统保管，复制程序目录不会复制登录状态。退出 Sticky 后再移动整个目录，更新时保留自己的 `Data`；目录应位于可写位置。

启动器和 WPF 程序均使用自包含单文件发布，运行时本机库会解压到系统临时目录。从 0.3.0 起，根目录的 `Sticky.exe` 是稳定启动器，实际程序在 `tools/runtime` 或已安装的版本目录；必须复制完整目录。默认数据仍在根目录的 `Data`，开机启动也指向根目录启动器。

0.6.1 修复启动期间普通窗口设为透明导致的黑屏：首次绘制显示正常底色和启动提示，并在真实 WPF 首帧绘制后确认就绪。已确认版本不再等待固定 2 秒才允许使用；稳定性观察在界面可用后继续，异常退出仍可回退且保留新编辑。首次安装和更新试启动仍在确认前禁用编辑并保留 2 秒保护，整包 SHA256 校验保持启用，同一文件不再重复哈希。开机启动在屏幕外完成管理页绘制，确认后隐藏，避免闪出管理窗口。

0.6.2 进一步并行启动：完整文件校验使用最多 4 个任务，并受可用处理器数量限制；只流式读取文件，不将整个程序包读入内存。便签、分组、布局、偏好和历史恢复在单个后台任务里按顺序准备，同时 UI 线程构建并绘制加载界面；数据准备完毕后才绑定视图、恢复便签和开放操作，控件与定时器始终由 UI 线程创建。恢复多张便签时合并布局保存和管理列表刷新，避免每开一张窗口都重复写盘和重建列表。程序校验、数据恢复及首次/更新试启动保护均未跳过。

便携版默认对启动器和应用使用 ReadyToRun 预编译，保留完整 IL 和 WPF 反射能力，不裁剪程序集。它对小工作空间没有明显额外收益，在本机多窗口测试中约再减少 0.2 秒，ZIP 约增加 8 MiB；可用 `scripts/package-portable.ps1 -ReadyToRun:$false -OutputDirectory <新目录>` 对比未预编译版本。本轮同机普通启动测试（每组首次之后四次取平均）：小工作空间从 1.76 秒到 1.53 秒；100 张合成短文本便签、恢复 10 个窗口时从 5.05 秒到 2.27 秒。数字为该机隔离测试，不代表其他硬盘、图片量和历史规模下的启动时间。

本次也优化了稳定启动器；手动测试时请退出旧版，将新包完整解压到新目录，再迁移自己的完整 `Data`，避免仅替换内部 exe。原目录的 `.sticky-launcher` 和 `versions` 属于原安装的更新恢复状态，请保留原目录以便回退。

开发者可用 `scripts/measure-startup.ps1 -PackageDirectory .\dist\Sticky-0.6.2-win-x64-portable -Background` 测量启动；去掉 `-Background` 测量普通双击模式。脚本复制程序到新的隔离目录，使用空白测试工作空间，不复制个人 Data；`results.json` 区分界面可用时间与启动器退出时间。设置 `STICKY_STARTUP_TRACE_DIR` 环境变量可记录按进程分开的启动阶段，仅包含阶段名、PID 和时间，不记录便签或凭据；默认关闭。运行时尚未执行托管代码前的耗时包含在端到端时间中，不能把它误算为数据加载耗时。
增加 `-NoteCount 100 -OpenNotes 10` 可自动生成合成便签和打开状态，测试批量恢复；不会读取真实便签。

开发者重新打包：

```powershell
.\scripts\package-portable.ps1
# 已存在的发布目录不会被覆盖，尤其不会删除便携数据；可指定另一个新目录
.\scripts\package-portable.ps1 -OutputDirectory .\dist\another-build
```

脚本校验官方 Git/GCM 下载包的 SHA256，生成自包含 exe、依赖组件、使用说明、许可证、版本清单、ZIP 和 ZIP 校验文件。开发机打包需要 .NET 10 SDK，目标电脑运行不需要。发布配置为 `src/Sticky.App/Properties/PublishProfiles/Portable.pubxml`，不裁剪 WPF 程序。

## AI 接入与自定义功能

在「设置 → AI 接入」配置 OpenAI 兼容 API 地址、模型和本机密钥，思考模式默认关闭，支持 DeepSeek 显式关闭思考和连接测试。「自定义功能」可编辑按钮名称、提示词、预设 SVG 图标及启用状态。选中文字后点击便签工具栏「AI」，从列表选择润色、翻译、提炼要点等自己配置的功能；预览并确认后仅替换原选区，支持撤销与本地历史记录。连接参数、思考开关、提示词和图标随 GitHub 同步，并发冲突保留双方；API 密钥按 Windows 当前用户加密，只留在本机，新设备需填写自己的密钥。断网时仍可正常编辑保存。详见 [AI 接入与自定义功能](docs/ai.md)。

## 版本与自动更新

从 0.2.0 开始，在「设置 → 版本与更新」查看当前版本、更新状态、发布说明，手动检查或选择「保存并重启更新」。默认开启自动更新：启动后约 30 秒检查，此后每 6 小时检查一次。网络或服务错误时约 15 分钟后重试，本地编辑与自动保存照常工作。只检查正式发布，不接受草稿、预览版、旧版或相同版本。

更新源固定为 `ZhangShiQi/Sticky` 的 GitHub Releases，与个人便签的同步仓库配置互相独立。公开和私有仓库均支持；私有仓库首次使用时，点击「登录并检查更新」，通过本机 Git Credential Manager 登录具有发行仓库读取权限的账号。后台只读取已有登录状态，不弹登录窗口；凭据仅在内存中用于该官方仓库的 GitHub API 请求，不写入更新配置或日志、不发送给下载重定向站点。没有仓库访问权限时明确报告错误；仓库可访问但尚无正式发布时，显示「当前没有更新的正式版本」。

发现新版本后，Windows x64 便携版自动下载完整 ZIP，核对 GitHub 提供的 SHA256、大小、包内版本、全部程序文件哈希及包内路径。就绪后有托盘提示，在下一次从托盘或设置退出时，先保存全部便签和窗口状态，启动器等待主程序退出后安装。关闭管理窗口只隐藏窗口，不会立即安装。取消自动更新后，仍可手动检查并安装，但退出时不会自动安装。

从 0.3.0 起，更新不覆盖根目录启动器或已确认的程序。新包完整校验后，放入 `versions/<版本>-<随机ID>`；启动器保存数据快照，在不可编辑、未开启同步的状态下初始化真实 WPF 窗口。只有私有命名管道完成进程身份和就绪确认、经过稳定观察，才原子提交版本指针并启用编辑。崩溃、超时、校验失败会保留旧版；试启动失败先恢复数据快照，再运行旧版，并隔离相同 SHA256 的失败包。已提交后再发生启动故障，只退回程序，保留升级后新写的便签。

`.sticky-launcher` 保存版本指针、待处理事务、独立提交记录及数据快照。启动器被强制结束时，Windows Job 会结束未确认的试启动程序；下次双击仍然从稳定入口读取事务并恢复。恢复过程本身也可在下次启动重试。数据快照不包含可重新下载的 `device/updates` 和本机 Git 缓存 `device/sync`，不会恢复或覆盖系统凭据。空间不足、数据不可读或快照校验失败时会停止操作，保留现场。不要手动删除 `.sticky-launcher`、正在使用的版本目录或自己的 `Data`；当前保留快照和旧版本，未自动清理。

程序目录须可写，数据不能与程序组件、版本目录或恢复目录重叠，路径不支持目录链接。运行状态位于 `Data/device/update-result.json`，启动器诊断位于 `.sticky-launcher/launcher-error.json`。启动器协议和数据格式目前固定为 1；不兼容包会拒绝自动安装，需要专门的迁移或手动升级。源码运行只检查版本。0.2.2 的旧更新器首次切换到新布局仍使用旧的原地替换方式；若首次新版启动失败，新启动器会尝试从已校验的 `.sticky-update-backup-*` 运行旧版，并暂停旧版自动更新。该过渡步骤不具备新布局所有阶段的中断保护。

0.1.x 没有更新客户端，需要先手动升级到 0.2.2 或更高版本：退出旧版，解压新包到原程序目录并保留 `Data`，之后可使用自动更新。
0.2.0 和 0.2.1 的更新辅助进程存在启动死锁，需手动升级至 0.2.2 或更高版本一次。若更新后无法启动，请保留 `Data`，先处理卡住且命令行包含 `--apply-update` 的辅助进程，再替换程序组件；不要结束正在编辑便签的进程。0.2.2 修复了该死锁。

### 发布新版本

`Directory.Build.props` 是唯一版本来源，所有程序集、设置页、打包名和发布清单共用。采用三段正式版本号：修订号用于修复、次版本用于兼容的新功能、主版本用于不兼容变更。历史见 [CHANGELOG.md](CHANGELOG.md)。

```powershell
.\scripts\set-version.ps1 -Version 0.2.1
# 更新 CHANGELOG.md，添加 [0.2.1] 节和用户可见变化
git add Directory.Build.props CHANGELOG.md # 以及本次功能涉及的源码
git commit -m "Release 0.2.1"
# 只预演，不访问远端，也不创建标签或发布
.\scripts\release.ps1 -WhatIf
# 本机测试、打包并上传发布（版本号自动读取，也可传 -Version 0.2.1 核对）
.\scripts\release.ps1
# 首次发布或登录失效时，由 Git Credential Manager 引导登录
.\scripts\release.ps1 -Login
```

默认使用本地发布，不使用 GitHub Actions。发布电脑需要 Windows、.NET 10 SDK、Git 和 Git Credential Manager，不需要 GitHub CLI。打包依赖会缓存在 `.tools/package-cache`，已校验的缓存可重复使用。GitHub 仅接收源码、版本标签以及 Releases 安装包；客户端仍按原方式自动更新。

发布前，将当前源码和发布脚本提交到本地 `main`。`release.ps1` 检查工作区干净、版本号与更新说明匹配、目标仓库正确、本地包含远端 `main` 的提交，且版本号不低于远端。通过 Git Credential Manager 读取 GitHub 登录状态，凭据只在内存中用于官方仓库的 API 请求。账号需要仓库写入权限；未登录可使用 `-Login`。`-WhatIf` 只预演，不访问远端、不读取凭据、不打包或创建发布。

检查通过后，本机运行发布脚本验证和完整应用回归测试，再在 `.tools/releases/<版本>-<随机ID>/` 生成新的 Windows 便携包，不复用可能过期的 `dist` 安装包。随后必须通过真实便携启动、版本安装及失败回退检查，才允许推送标签。测试使用明确标记的隔离工作空间和实例，不操作用户当前便签。保留 `STICKY_TEST_FILTER` 会直接阻止正式发布。版本、平台、ZIP 和便携检查通过后，再次确认源码没有变化，然后推送 `main` 与版本标签，上传 ZIP 和 `.sha256` 到草稿 Release。两份资源的 GitHub SHA256 摘要均核对成功后才正式发布并标记为最新版。

测试、打包或校验失败会在推送前停止；上传失败保留草稿，同一提交可重新执行发布命令继续。已发布的版本和指向其他提交的标签不会覆盖；修改源码后应使用新版本号。脚本不自动加入文件、不自动提交、不强制推送。请避免同时在两台电脑发布同一版本。当前工程已移除自动云端打包工作流，发布标签不会触发本工程的 Actions；如以前手动配置过其他工作流，其运行规则需单独管理。

使用本机资源构建不消耗 GitHub Actions 分钟数或 Actions 产物存储。公开仓库的标准 Actions runner 免费，私有仓库有套餐内额度，超额可能收费，见 [GitHub Actions 计费](https://docs.github.com/en/billing/concepts/product-billing/github-actions)。Releases 资源与 Actions 产物是不同的功能，更新客户端使用 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases)。

## 从源代码启动

在 Windows 上双击根目录的 `run.cmd`。它会构建 Release 版本并启动应用。

`run-demo.cmd` 使用项目内的 `.local-demo` 数据目录，可以继续打开开发预览时写下的便签；它与默认工作空间彼此独立。重新构建前请从管理页或托盘菜单选择「退出 Sticky」，避免后台进程占用程序集。

需要 .NET 10 SDK，可从 <https://dotnet.microsoft.com/download/dotnet/10.0> 安装。脚本优先使用可选的项目内 SDK（`.tools/dotnet`），否则使用系统安装的 SDK；本地 SDK 不加入版本控制。

也可以在 PowerShell 中运行：

```powershell
.\run.ps1
# 使用独立的数据目录，便于测试或做便携工作空间
.\run.ps1 -DataDirectory .\.local-demo
# 已构建时直接启动
.\run.ps1 -NoBuild
```

使用 Visual Studio 时，打开 `Sticky.sln`，将 `Sticky.App` 设为启动项目。SDK 版本由 `global.json` 指定。

## 本地版已实现

- 多个独立便签窗口；同一便签只打开一个窗口。
- 在便签里点击「＋」或按 Ctrl+N，新便签在当前便签附近打开，并保留当前分组。连续新建时读取其他便签的实时位置，优先利用右侧、左侧、上下及周围空隙，尽量保持间距；空间紧张时先紧凑摆放，附近确实放不下才错开叠放，避免反复落到同一位置或跳到远处。最小化和隐藏的便签不占位置，已有窗口保持原位置；使用当前显示器的工作区，避开任务栏和屏幕边缘，并保存最终窗口位置。
- 手动标题优先；未设置或清空标题时，自动使用正文第一行有效文字（跳过空白行和图片）。正文完全没有文字时显示「未命名便签」；修改首行后自动更新管理页、搜索结果和窗口标题，不会把推导标题写回手动标题字段。
- 无 Windows 标准标题栏的深色便签；顶部显示实际标题，默认始终显示。长标题省略，悬停可查看完整内容；正文首行、手动标题及同步修改会及时更新可见标题。
- 点击正文或按 F2 进入编辑并显示底部单行格式栏，切换窗口或按 Esc 完成编辑。「设置 → 编辑与排版 → 自动隐藏便签标题栏」默认关闭，旧版配置升级后也保持显示。开启后，阅读空闲时收起为窄色条，可选择悬停展开；编辑、拖动或菜单操作期间保持显示，避免输入法候选框造成闪烁和正文跳动。悬停不会进入编辑或显示底部格式栏。
- 新便签默认从五种颜色中随机选择，并保存选中的颜色；「设置 → 编辑与排版」可关闭随机颜色，关闭后新便签使用暖黄，已有便签保持原色。交互设置点击「保存并应用」后对已打开便签生效，仅保存在本机。
- 顶部保存状态与「···」之间提供当前颜色方块，点击弹出五种颜色列表，选中后立即更新便签和管理页卡片并自动保存。标题、字号、文字颜色、置顶、分组等通过「···」菜单设置。
- 拖动顶部色条移动便签，拖动边缘调整大小；窗口大小和位置恢复。
- 富文本：加粗、斜体、下划线、删除线、字号、文字颜色、项目列表和编号列表。
- 新建、回车输入、列表和保存后重开均使用同一段落间距；行高自然适应字体和图片，不用固定行高裁剪内容。
- 「设置 → 编辑与排版」统一调整默认字号（10–48）和段落间距（0–32），单位为逻辑像素；已打开的便签立即应用，新建、重开和重启保持一致。默认值为 16 和 8，手动指定过字号的文字保留其大小。排版偏好仅保存在本机，不参与 GitHub 同步；旧便签中大小为 16 的文字视为默认字号，其他大小保留。
- 图片：文件选择、拖入、剪贴板截图粘贴；图片右键可切换小/中/大尺寸及移除。
- 输入停止 600 ms 后自动保存；关闭窗口和退出前强制补存。失败时保留编辑内容并阻止关闭，支持 Ctrl+S 重试。
- 管理页左侧统一为「工作空间」：全部便签、自定义分组、未分组、回收站。支持创建和重命名分组，在卡片的分组按钮或便签菜单里移动便签；空分组也会保留，当前所在项目会高亮。
- 工作空间列表下方提供搜索框，输入关键词并按 Enter 后才打开搜索结果；Ctrl+F 聚焦搜索框。结果窗口搜索标题和正文，可按分组筛选；双击结果或按 Enter 打开便签。
- 左侧底部只有统一「设置」入口，不显示同步状态或数据操作按钮。设置窗口分类为「同步」「数据与备份」「编辑与排版」「应用」，包含仓库配置、同步状态、数据及备份目录、备份导入导出、字号和段落间距、版本与退出功能；切换分类保留未保存的表单。
- ZIP 备份导出和导入，含分组、回收站和图片。导入相同便签 ID 时生成新副本；分组按名称合并，ID 冲突时重新映射。
- 原子文件替换、上一版本 `.bak` 备份、损坏便签恢复提示；应用在当前 Windows 用户会话内仅运行一个实例，重复启动会退出新进程并唤起已有管理页，不受 exe 位置或数据目录影响。开机启动重复运行时安静退出。升级前请先从托盘退出旧版本。

快捷键：Ctrl+N 新建，Ctrl+F 打开独立搜索，Ctrl+S 保存，F2 编辑，Esc 完成编辑，Ctrl+B / I / U 修改格式，Ctrl+Z / Y 撤销/重做正文编辑。在分组页新建便签会自动放入该分组。

关闭某张便签只关闭窗口，内容仍在管理页。关闭管理页会保存并隐藏管理窗口，打开的便签继续显示，应用留在系统托盘。双击托盘图标或使用便签「··· → 便签管理」可以重新打开管理页。彻底退出请使用「设置 → 应用 → 退出 Sticky」或托盘的退出入口；下次启动恢复退出时打开的便签。

「设置 → 应用 → 开机自动运行」默认关闭，勾选即生效，不需要管理员权限。登录 Windows 后恢复之前打开的便签，管理页留在托盘；不会凭空新建空白便签。启动命令记录当前程序和绝对数据目录，支持便携 exe 和通过 dotnet 启动的开发版。每个 Windows 用户保留一个 Sticky 启动项，启用新位置会替换旧位置；移动程序或数据目录后，请在新位置重新开启。它不参与 GitHub 同步，也不会因复制 Data 到另一台电脑而自动启用。实现使用当前用户的 [Windows Run 启动项](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)；若在 Windows 的启动应用设置中禁用了 Sticky，需要在系统设置中重新允许它运行。

应用图标源文件为 `src/Sticky.App/Assets/Sticky.svg`，墨绿底色配暖黄折角便签。exe、窗口、任务栏、托盘和侧栏使用同一设计；侧栏为矢量，Windows ICO 包含 16–256 像素的 9 种尺寸。修改 SVG 后运行 `powershell.exe -NoProfile -STA -File scripts/generate-icon.ps1`，即可重新生成 ICO、WPF 矢量资源和预览，无需第三方工具。便携包同时附带 `assets/Sticky.svg`。

## 数据与备份

默认位置：`%LOCALAPPDATA%\Sticky\Data`。可从「设置 → 数据与备份」查看和打开。

```text
Data/
  manifest.json
  groups.json             # 自定义分组及其稳定 ID，含空分组
  notes/<guid>.json       # 正文、标题、颜色、分组 ID、时间、删除标记
  assets/<sha256>.png     # 正文引用的独立图片
  device/windows.json    # 本机窗口状态，不属于共享正文
  device/editor.json     # 本机默认字号、段落间距、随机颜色与悬停开关
  backups/               # 自动备份的专用目录，按原文件路径分类
    notes/<guid>.json.bak # 便签上一次成功保存的版本
    groups.json.bak
    device/...           # 窗口、排版、同步配置及同步基线备份
    corrupt/...          # 恢复前保留的损坏原文件
    legacy/...           # 迁移时遇到同名备份，额外保留的副本
```

JSON 是正文的唯一事实来源。图片以内容哈希去重；使用相对资源标识，不依赖原文件位置。正文保存前图片已落盘。窗口布局独立保存，不参与 Git 同步。

检测到无效便签 JSON 时，尝试读取 `backups` 中的 `.bak`，将损坏原文件保留到 `backups/corrupt` 并提示用户；无法恢复的文件不删除。比当前版本更新的数据格式会保留并跳过，不会降级写回。升级时自动将原先与正常文件并排的 `.bak` 移入专用目录，重名时保留双方备份；迁移失败则保留旧文件并提示。自动备份只保留上一版本，建议定期导出 ZIP。

便签、图片与 ZIP 均以明文保存。回收站目前不提供永久删除；移除图片后保留资源文件，避免影响备份与历史恢复。请使用应用内的 GitHub 同步入口，不要直接同步运行中的整个数据目录。

## 本地历史与重放

本地历史独立于 GitHub。在管理页「时间轴」、便签「··· → 历史版本与重放」或「设置 → 历史与重放」打开统一时间轴。左侧多选便签，右侧顶部统一显示时间刻度，工作空间以「SVG 操作图标 + 下方便签标题」逐项展示，便签轨道复用相同图标，悬停可读操作说明，点击可精确定位；下方同时显示所选便签在该时刻的富文本和图片，支持回放、对比及恢复。窗口位置等界面操作不进入用户时间轴。播放不修改当前工作空间；恢复追加新记录。历史保存在 `Data/history`，不会随 Git 同步上传，连续输入合并展示；可以从时间轴导出完整历史备份。详情与格式见 [本地时间轴与重放](docs/history.md)。

## GitHub 同步

默认不开启。仓库地址和同步分支均可配置，不绑定任何固定账号或仓库。

1. 安装 Git for Windows，并包含 Git Credential Manager（本机已安装）。
2. 在 GitHub 创建专门的**私有仓库**；可以是空仓库，也可以已有 README。
3. 在管理页左下角、托盘或便签「···」菜单打开「设置」，选择「同步」。
4. 输入 `https://github.com/账号/仓库.git`，分支默认 `sticky-data`，勾选「启用 GitHub 同步」，保存配置。
5. 点击「立即同步」。如尚未登录，Git Credential Manager 会引导完成 GitHub 登录；账号需要对目标私有仓库有写权限。不要在地址中填令牌或密码。
6. 在另一台电脑填写同一个仓库地址和分支，即可下载便签并开始双向同步。

凭据由 Git Credential Manager 和系统凭据存储管理，应用不保存 GitHub 密码或令牌。首次登录和登录过期请手动点击「立即同步」；后台同步不弹登录窗口。GCM 的能力及配置见[官方说明](https://github.com/git-ecosystem/git-credential-manager)。当前配置界面支持 `github.com` 的 HTTPS 仓库，不支持 SSH 或 GitHub Enterprise。

本地变更约 15 秒后批量同步，空闲时约每分钟检查一次其他设备的改动。失败后按 30、60、120、240、300 秒退避重试；可以手动立即重试或取消。网络操作在后台执行，断网、权限不足、登录失效或仓库不可用均不影响本地自动保存。配置窗口显示具体错误和重试状态。停用同步只停用后台检查，不删除本地或远端数据。

便签同步数据在目标分支的 `sticky-v1/` 下，包括便签 JSON、分组、图片、回收站中的删除标记；共享 AI 连接参数与自定义功能独立存放在 `sticky-ai-v1/settings.json`，并发修改保留双方。首次推送会创建配置的分支，不自动创建 GitHub 仓库。该分支既有的其他文件会保留。窗口位置、设备设置、同步配置、API 密钥等凭据、`.bak` 和损坏文件不会上传；本地 Git 缓存与共同版本放在 `device/sync/<目标哈希>/`，切换仓库或分支会使用独立缓存。

同步规则：

- 以共同版本、本地版本和远端版本做三方比较，不依赖设备时钟判断胜负。
- 不同便签的修改自动合并；同一便签只要双方都发生不同修改，就保留原版本并生成「冲突副本」，包含完整富文本和图片引用，不做逐行文本合并。
- 删除与修改冲突时，两种状态都保留。未删除的内容仍可查看，删除的版本位于回收站；冲突副本带有原便签标识。
- 已有冲突副本再次同步不会重复生成；副本后来被修改过时，也不会用旧内容覆盖它。
- 同步期间继续输入的文字保留在当前编辑器，竞争的远端版本另存副本。新下载的便签显示在管理页，不会自动弹出大量窗口。
- 分组按稳定 ID 合并；不同设备创建同名分组会合并成员，分组重命名冲突保留两个名称。
- 图片使用内容哈希校验，先保存图片和冲突副本，再更新现有便签。无效 JSON、缺图或不支持的数据格式会停止该轮同步，不覆盖健康本地数据。
- 遇到其他设备抢先推送时，重新获取并比较，最多立即重试三轮；不强制推送，不回滚本地正文。
- 实际删除只通过便签的回收站标记传播。手工从 Git 仓库删除 JSON 不表示删除便签，下一轮可能重新上传。

当前每轮同步的数据限制为 10000 个文件、单文件 20 MB、`sticky-v1` 数据总计 256 MB。图片会进入 Git 历史，频繁更新大量图片会增加仓库体积。私有仓库提供访问控制，数据内容仍为明文，没有端到端加密。

## 编辑器边界

- 只保存受控的段落、文字样式、列表和图片，不加载外部 XAML 或 HTML。
- 从其他软件粘贴的文字会移除外部格式；截图可直接粘贴。应用内富文本可以正常编辑与保存。
- 单张导入图片上限 20 MB，保存为最长边至多 1600 像素的 PNG；GIF 保存当前静态帧，不保留动画/原图。
- 不支持复杂表格、任意字体、任务复选框或多人协作。
- 图片尺寸调整与便签标题/颜色不参与正文撤销栈。
- 打开便签时保留其所在显示器的位置；若显示器已移除，则限制到最近显示器的工作区，避免窗口不可见。
