# 本地时间轴与重放

0.5.0 新增本地历史与重放。历史自动启用，离线可用，不依赖 GitHub。GitHub 同步继续只传便签当前状态、分组和图片；每台电脑记录自己观察到的历史，不合并其他设备的完整历史日志。

## 使用

- 管理页「时间轴」、托盘「时间轴与重放」打开全局视图。
- 左侧列表可多选便签，也可全选或清空。便签「··· → 历史版本与重放」及管理卡片菜单打开时预选该便签，回收站便签也可查看。
- 工作空间与所选便签轨道放在同一滚动区域，共用顶部日期、秒级时间刻度和时间指针。工作空间逐项展示操作节点，以「SVG 图标在上、便签标题在下」排列；便签节点仅显示同一套操作图标，时间只在顶部对应列展示。悬停提示保留操作名称、完整标题、时间及变更说明，无障碍名称同样包含操作含义；点击直接定位该次操作，与下方便签的对应节点垂直对齐。多选仅改变展开的轨道和内容预览，不过滤全局节点、不重置当前时刻，清空选择后仍可浏览全局。横向滚动时轨道名称固定在左侧。
- 时间轴展示正文/富文本/图片、标题/颜色、分组移动和重命名、删除恢复；窗口位置、大小、置顶和打开关闭保留在内部历史中，不作为用户事件或回放步骤，也不影响预览排版。
- 点击工作空间或便签事件、拖动进度或上/下一步查看历史状态。下方内容卡片显示所选便签在同一时刻的富文本和图片，未创建及回收站状态有明确提示；点击卡片标题打开完整内容对比、变更详情和恢复入口。可拖动中间分隔条调整轨道与预览高度。
- 播放支持 0.5×/1×/2×/4×/8×。选中便签后，播放和上/下一步跳过无关便签；清空选择时播放全局变化。工作空间节点及进度条始终能定位全局时刻。默认跳过空闲，将长间隔压缩为 2 秒；取消后按真实记录间隔播放。播放的是保存批次，不是每次按键，也不声称还原真实输入轨迹。
- 同一便签、同一编辑会话中，相邻间隔不超过 30 秒的连续修改在界面合并为一个批次，穿插的窗口操作和其他便签保存不会打断；分组操作、删除恢复和新会话形成独立批次。底层仍保留实际持久化记录，便于中断恢复。
- 「恢复为新便签」创建副本；「恢复到当前便签」需明确确认，替换标题、颜色、分组和正文并恢复为活动便签，窗口位置保持当前。两者都会追加新记录，旧内容仍可查看。图片缺失/哈希不符时在修改前拒绝恢复。
- 重放完全使用独立的历史模型，不关闭/移动真实便签，不写回、不触发同步。实时编辑或同步仍可继续；有新事件时提示刷新，当前播放视图保持稳定。
- 启用前的数据作为初始快照，无法补记此前的操作。同步记录的时间是本机接收时间，详情同时显示原内容修改时间；旧版或外部变动标记为检测时间。

## 本地格式与一致性

```text
Data/history/
  baseline.json                启用时的文档引用及完整性校验
  events/<20位顺序号>.json     不可变事件、来源、变更说明和前后对象引用
  objects/<sha256>.json        去重的完整 JSON 状态；富文本保留原模型
  checkpoints/<顺序号>.json   每 100 个事件的全局引用快照，可由事件重建
  head.json                    最新顺序号
  pending.json                 尚未完成的单文档保存事务
  recovery/                    无法与当前文件匹配的未完成记录，隔离保留
  writer.lock                  本机写入串行化锁
Data/assets/<sha256>.png        当前内容和历史共享的图片，不重复复制
```

先持久化历史对象和待提交记录，再通过现有原子写入保存便签/分组/布局，随后发布事件和顺序号。写入中断后：当前文档与新对象匹配则补齐事件；仍为旧对象则取消未完成事件；两者都不匹配则隔离记录，绝不使用旧历史覆盖当前文件。历史索引暂时不能写入而正文已落盘时，保留待提交记录并承认正文已保存，下一次访问补齐提交。日志、对象和检查点有完整性校验；检查点损坏可从事件重建。

事件顺序以本机持久化顺序号为准，设备时钟回拨不会重排事件。从不依赖 Git 提交时间推断本地先后。图片采用已有内容标识，当前版本移除图片后也保留历史引用所需的文件。当前保留全部历史，不提供自动清理，也不会删除用户历史来腾空间。

当旧版 Sticky 或外部工具修改了当前 JSON，新版启动/刷新时比较当前文件与历史投影，补记观察到的变化；不会把旧历史强制写回当前便签。未记录期间的中间步骤无法补全。不能把检测时间当作外部操作的准确发生时间。

## 备份

时间轴中的「导出历史」生成包含当前便签、分组、所有图片、窗口状态和完整历史的 ZIP。同步配置、账号凭据、Git 缓存及写入锁不导出。恢复时退出 Sticky，将 ZIP 完整解压到新的空 Data 目录，使用该工作空间启动；不要与正在使用的 Data 合并。ZIP 内有说明。

原有「数据与备份 → 导出备份」是普通便签迁移备份，不包含时间轴；导入这些便签会记为新导入事件。普通导入拒绝完整历史 ZIP，避免 ID 重映射时混淆历史。直接在退出后复制整个 Data 同样保留本地历史。

## 验证边界

专项测试覆盖各类变更与前后模型、连续输入批次、旧数据基线、检查点损坏重建、真实文件锁/索引写入失败、完整历史 ZIP 往返、同步来源、无效恢复保护，以及保存准备/正文写入/事件发布三个阶段强制结束子进程后的恢复。WPF 测试验证原生勾选绑定、多选/清空后全局不变且时间指针不跳、选中便签的播放和步进、回收站预览及最小窗口布局；遍历播放帧并检查当前数据哈希不变，再验证副本恢复和当前便签恢复。

本功能未执行物理断电或磁盘损坏测试；文件校验用于检测损坏，不意味着能恢复已丢失的全部磁盘内容。不要手动改写 history 文件或删除仍被历史引用的图片。
